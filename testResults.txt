Packet Loss Testing:

    To test for packet loss, I ran this command in my machine to give packets a 30% change of being lost:

    sudo tc qdisc add dev lo root netem loss 30%

    Test #1:
        I then sent 10 messages from one client (A-J). 
        The server didn't receive the A or the I packet. (2/10 loss)
        Of the 8 packets that the server sent back, the sending client didn't receive the B, D, or F packet. (3/8 loss)
        The other client that was connected didn't recieve the H or J packet. (2/8 loss)

    Test #2 (Duplicate):
        Sent 10 messages from one client (A-J).
        The server didn't receive the C, F, H, or I packet. (4/10 loss)
        The sending client didn't get back the G or J packet. (2/6 loss)
        The other client didn't get back the D or E packet. (2/6 loss)

    Total packets sent: 48
    Total packets lost: 15
    Percent Lost: 31.3%
    Condition: Each packet was considered as two packets, one going from client to server and one from server to client.

    Note: There were no crashes, disconnects, or resends because the UDP protocol does not check for complete arrival. 


Packet Order Testing:

    To test packet arrival order, I ran this command in my machine to give 25% packets a 50% chance of being rearranged:

    sudo tc qdisc add dev lo root netem delay 100ms 20ms reorder 25% 50%

    I also adjusted my sending code to send 10 messages in quick succession using a loop.

Connectionless Protocol Testing:

    To test whether there could be issues with sending data to the wrong client, I set up two clients. The server sent responses to both clients. Then I closed one client, but the server still attempted to send responses to both. Since there is no official connection, the server has no way of knowing if a client is actually receiving messages, so it simply sends out messages to all the addresses it has received from until they time out. This means that if a new client would join using the previous client's old address, they would receive messages intended for the previous client.

    Similarly, if the server restarts, clients will continue messaging the server as if nothing has happened, because there is no official connection.
